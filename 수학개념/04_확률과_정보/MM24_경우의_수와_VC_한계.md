> [!NOTE]
> **3줄 요약**
> - 단어 m개 중에서 n개를 골라(중복 허용) 줄 세우는 방법은 $m^n$가지다. 과일 30개로 10개짜리 목록을 만들면 $30^{10} = 590{,}490{,}000{,}000{,}000$ (약 590조)가지다.
> - 점 n개에 +1/−1 라벨을 붙이는 방법(**[이분법](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#dichotomy-%EC%9D%B4%EB%B6%84%EB%B2%95)**)은 $2^n$가지다. 모형이 그중 몇 개를 만들 수 있는지가 VC 이론이 재는 "모형의 크기"다.
> - 강의 슬라이드의 한계 $\sqrt{d/n}$에서 모형이 모든 [이분법](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#dichotomy-%EC%9D%B4%EB%B6%84%EB%B2%95)을 만들면 $d = 2^n$이라 n = 20에서 228.97이 된다. [오차](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#error-%EC%98%A4%EC%B0%A8) 한계가 100%(= 1)보다 크면 아무 말도 해 주지 않는다(vacuous).

## 1. 개념 설명

비유: 자물쇠 번호가 0~9 숫자 4자리면 $10^4 = 10{,}000$가지다. 자리마다 10가지를 고르고, 자리끼리는 서로 상관없으니 곱한다. "칸마다 선택지 수를 곱한다"가 경우의 수의 기본이다.

- **순서 있는 목록의 수**: 칸 n개, 칸마다 선택지 m개 → $m × m × \cdots × m = m^n$
- **[이분법](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#dichotomy-%EC%9D%B4%EB%B6%84%EB%B2%95)**: 점마다 선택지가 +1, −1 두 개 → $2^n$
- **[VC 차원](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#vc-dimension-vc-%EC%B0%A8%EC%9B%90)과 [일반화 한계](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#generalization-bound-%EC%9D%BC%EB%B0%98%ED%99%94-%ED%95%9C%EA%B3%84)**: [가설 공간](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#hypothesis-space-%EA%B0%80%EC%84%A4-%EA%B3%B5%EA%B0%84)이 만들 수 있는 [이분법](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#dichotomy-%EC%9D%B4%EB%B6%84%EB%B2%95)이 적을수록, 데이터 n이 많을수록 "[학습 데이터](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#training-data-test-data-%ED%95%99%EC%8A%B5-%EB%8D%B0%EC%9D%B4%ED%84%B0%EC%99%80-%EC%8B%9C%ED%97%98-%EB%8D%B0%EC%9D%B4%ED%84%B0)를 우연히 맞춘 가짜 함수(거짓 양성)"를 고를 위험이 줄어든다. 강의 슬라이드는 이를 $\sqrt{d/n}$으로 적는다.

## 2. 필요한 이유

- [Lec06 3.2](../../Lec06_%EC%9D%BC%EB%B0%98%ED%99%94_%EC%9D%B4%EB%A1%A0.md#32-llm%EC%9D%80-%ED%8C%8C%EC%9D%BC-%EC%BA%90%EB%B9%84%EB%8B%9B%EC%9D%B8%EA%B0%80): "LLM이 외우기만 한다면 캐비닛이 얼마나 커야 하나"를 $s = p \cdot m^n$으로 센다. 그 수가 [학습 데이터](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#training-data-test-data-%ED%95%99%EC%8A%B5-%EB%8D%B0%EC%9D%B4%ED%84%B0%EC%99%80-%EC%8B%9C%ED%97%98-%EB%8D%B0%EC%9D%B4%ED%84%B0)보다 훨씬 크면 외우기만으로는 설명이 안 된다.
- [Lec06 7](../../Lec06_%EC%9D%BC%EB%B0%98%ED%99%94_%EC%9D%B4%EB%A1%A0.md#7-vc-%EC%9D%B4%EB%A1%A0%EA%B3%BC-%EA%B7%B8-%ED%95%9C%EA%B3%84): 신경망은 무작위 라벨도 다 맞추므로 $2^n$개 [이분법](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#dichotomy-%EC%9D%B4%EB%B6%84%EB%B2%95)을 모두 만든다. 그래서 VC 한계가 쓸모없어진다는 논증이다.

## 3. 숫자로 보기

**캐비닛 크기 세기** (강의 실험)

| 실험 | m (어휘) | n (길이) | $m^n$ | 맞힌 비율 p | $s = p \cdot m^n$ |
|---|---|---|---|---|---|
| 감귤류 세기 (텍스트) | 30 | 10 | 590,490,000,000,000 | 1 (5/5) | 약 590조 |
| 과일 그리기 (이미지) | 30 | 10 | 590,490,000,000,000 | 0.125 (1/8) | 약 73.8조 |

(강의 슬라이드는 n = 30, m = 10으로 적고 100조와 12.5조라고 했지만, 정의대로 계산하면 위 표처럼 약 590조와 73.8조다. 어느 쪽이든 결론은 같다.)

**[이분법](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#dichotomy-%EC%9D%B4%EB%B6%84%EB%B2%95) 세기**: 점 3개 (x = 1, 2, 3)
- 가능한 라벨 묶음: $2^3 = 8$가지 (−−−, −−+, −+−, −++, +−−, +−+, ++−, +++)
- 문턱 분류기 "x > t이면 +1"이 만드는 것: −−−, −−+, −++, +++ → **4가지**뿐이다. −+− 같은 것은 못 만든다.
- 이 분류기는 점 1개는 두 라벨 모두 만들 수 있지만 점 2개 (1, 2)에서 +−는 못 만든다. 그래서 [VC 차원](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#vc-dimension-vc-%EC%B0%A8%EC%9B%90)은 1이다.

**후보 함수 고르기** (강의의 동그라미 그림)
- [학습 데이터](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#training-data-test-data-%ED%95%99%EC%8A%B5-%EB%8D%B0%EC%9D%B4%ED%84%B0%EC%99%80-%EC%8B%9C%ED%97%98-%EB%8D%B0%EC%9D%B4%ED%84%B0)를 맞추는 후보가 6개이고 그중 하나가 참 함수면, 아무거나 고를 때 참 함수일 [확률](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#probability-%ED%99%95%EB%A5%A0)은 $1/6$
- 데이터를 더해 후보가 4개로 줄면 $1/4$로 오른다

**슬라이드의 한계** $\sqrt{d/n}$

| n | $d = 2^n$일 때 | $d = 1000$일 때 |
|---|---|---|
| 10 | $\sqrt{1024/10} = 10.12$ | $\sqrt{100} = 10$ |
| 20 | 228.97 | 7.0711 |
| 1,000 | (천문학적) | 1 |
| 100,000 | (천문학적) | 0.1 |

- d가 고정이면 n을 늘릴수록 한계가 0으로 간다. d = 2ⁿ이면 n을 늘릴수록 한계가 오히려 폭발한다.

## 4. 코드로 확인

```python
# [변수] m = 30: 과일 이름 어휘 수, n = 10: 목록 길이. 강의 실험의 값
m, n = 30, 10
# [함수] **: 거듭제곱. m ** n = 30을 10번 곱한 값
# [변수] seqs = 590490000000000: 가능한 입력 목록의 수 (약 590조)
# [연결] 본문 3절 첫 표의 m^n
seqs = m ** n
# [함수] int(): 소수점을 버려 정수로. 0.125 × seqs는 정확히 73811250000000.0이다
# [연결] 텍스트 p = 1, 이미지 p = 0.125일 때 캐비닛 크기 s = p·m^n
print(seqs, int(1 * seqs), int(0.125 * seqs))
# [변수] pts = [1 2 3]: 이분법을 셀 점 세 개
pts = np.array([1, 2, 3])
# [함수] set(): 중복 없이 모으는 상자. 같은 라벨 묶음은 한 번만 센다
# [변수] labels: 문턱 분류기가 만든 라벨 묶음들
labels = set()
# [변수] t: 문턱 값. 점 사이와 바깥(0.5, 1.5, 2.5, 3.5)만 보면 모든 경우가 나온다
for t in [0.5, 1.5, 2.5, 3.5]:
    # [함수] np.where(pts > t, 1, -1): 문턱보다 크면 +1, 아니면 -1. tuple로 바꿔 set에 넣는다
    labels.add(tuple(np.where(pts > t, 1, -1)))
# [연결] 4 8 → 가능한 8가지 중 4가지만 만든다 (본문 3절 이분법 세기)
print(len(labels), 2 ** len(pts))
# [함수] np.sqrt: 제곱근. round(·, 2): 소수 둘째 자리
# [연결] 슬라이드의 한계 √(2ⁿ/n): n = 10 → 10.12, n = 20 → 228.97 (본문 3절 마지막 표)
print(round(np.sqrt(2 ** 10 / 10), 2), round(np.sqrt(2 ** 20 / 20), 2))
```

**실행 결과**:

```text
590490000000000 590490000000000 73811250000000
4 8
10.12 228.97
```

> [!WARNING]
> **⚠ 주의**
> - 강의 슬라이드는 "d = [이분법](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#dichotomy-%EC%9D%B4%EB%B6%84%EB%B2%95)의 수"라고 적었지만, 교과서에서 **[VC 차원](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#vc-dimension-vc-%EC%B0%A8%EC%9B%90)**은 "모든 [이분법](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#dichotomy-%EC%9D%B4%EB%B6%84%EB%B2%95)을 만들 수 있는(shatter) 점의 최대 개수"다(위 문턱 분류기는 1). [이분법](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#dichotomy-%EC%9D%B4%EB%B6%84%EB%B2%95)의 수 자체는 성장 함수(growth function)라 부르고, 정식 한계에는 그 수의 [로그](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#log-ln-%EB%A1%9C%EA%B7%B8)가 들어간다. 그래도 신경망처럼 n개 점의 $2^n$개 [이분법](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#dichotomy-%EC%9D%B4%EB%B6%84%EB%B2%95)을 모두 만들면 정식 한계도 0으로 줄지 않아 쓸모없다는 결론은 같다.
> - 캐비닛 크기 실험의 p는 5번, 8번 시도로 잰 거친 추정이다. 강사도 "가장 좋은 실험은 아니다"라고 말한다.

## 5. 개념 재확인

<details><summary>1. 명사 1000개로 5개짜리 목록을 만든다. 모형이 절반(p = 0.5)을 맞힌다면 캐비닛은 몇 개의 항목이 있어야 하나?</summary>

| 단계 | 하는 일 | 식 | 계산 | 결과 |
|---|---|---|---|---|
| 1 | 목록의 수 | $m^n$ | $1000^5$ | $10^{15}$ |
| 2 | 맞힌 비율 곱하기 | $p \cdot m^n$ | $0.5 × 10^{15}$ | $5 × 10^{14}$ |
| 3 | 읽기 | - | 500,000,000,000,000 | 500조 |

**① 쓰는 식**
$$s = p \cdot m^n$$
- 위 식 ← ② (목록의 수)에서 $m^n$을, ③ (비율 곱하기)에서 $p$를 곱한다.
```python
# [변수] m = 1000: 명사 어휘 수, n = 5: 목록 길이, p = 0.5: 맞힌 비율. 문제에서 준 값
m, n, p = 1000, 5, 0.5                    # ①
# [변수] seqs = 10¹⁵: 가능한 목록의 수
seqs = m ** n                             # ②
# [변수] s = 5×10¹⁴: 캐비닛 크기. int로 정수 출력
s = int(p * seqs)                         # ③
# [연결] 1000000000000000 500000000000000
print(seqs, s)
```

**문제**: 명사 1000개로 5개짜리 목록을 만든다. 모형이 절반(p = 0.5)을 맞힌다면 캐비닛은 몇 개의 항목이 있어야 하나?

**주어진 값**:
- $m = 1000$ (어휘 수)
- $n = 5$ (목록 길이)
- $p = 0.5$ (모형이 맞힌 비율)

**풀이**
1. 식을 그대로 쓴다: $s = p \cdot m^n$
2. 값을 대입한다: $s = 0.5 \times 1000^5$
3. (②) 거듭제곱을 푼다 ($1000^5$은 1000을 5번 곱한다는 뜻): $1000 = 10^3$ 이고 [지수](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#e-exponent-e%EC%99%80-%EC%A7%80%EC%88%98)는 곱해지므로 $(10^3)^5 = 10^{3 \times 5} = 10^{15}$ 이므로 $s = 0.5 \times 10^{15}$
4. (③) 곱셈을 한다: $0.5 \times 10^{15} = 5 \times 10^{14}$ 이므로 $s = 5 \times 10^{14}$
5. 읽는다: $5 \times 10^{14} = 500{,}000{,}000{,}000{,}000$ (500조)

**답**: **5 × 10¹⁴ (500조)** 개. [학습 데이터](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#training-data-test-data-%ED%95%99%EC%8A%B5-%EB%8D%B0%EC%9D%B4%ED%84%B0%EC%99%80-%EC%8B%9C%ED%97%98-%EB%8D%B0%EC%9D%B4%ED%84%B0) 수십조 [토큰](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#token-%ED%86%A0%ED%81%B0)보다 크므로 외우기만으로는 설명이 안 된다.

<details><summary>2. n = 30일 때 슬라이드 한계 $\sqrt{d/n}$를 d = 2ⁿ과 d = 1000에 대해 구하고, d = 1000에서 한계가 0.1이 되려면 n이 얼마여야 하나?</summary>

| 단계 | 하는 일 | 식 | 계산 | 결과 |
|---|---|---|---|---|
| 1 | d = 2³⁰ | $\sqrt{2^{30}/30}$ | $\sqrt{35{,}791{,}394.13}$ | 5982.59 |
| 2 | d = 1000 | $\sqrt{1000/30}$ | $\sqrt{33.33}$ | 5.7735 |
| 3 | 한계 0.1이 되는 n | $1000/n = 0.01$ | $n = 1000/0.01$ | 100,000 |

**① 쓰는 식**
$$\text{한계} = \sqrt{d / n} \quad\Rightarrow\quad n = d / \text{한계}^2$$
- 위 식 ← 왼쪽은 ② (d = 2³⁰)와 ③ (d = 1000), 오른쪽은 ④ (필요한 n)에서 쓴다.
```python
# [변수] n = 30: 학습 데이터 수. 문제에서 준 값
n = 30                                            # ①
# [연결] d = 2³⁰ → 5982.59 (100%를 한참 넘는 쓸모없는 한계)
print(round(np.sqrt(2 ** n / n), 2))              # ②
# [연결] d = 1000 → 5.7735 (아직 1보다 크다)
print(round(np.sqrt(1000 / n), 4))                # ③
# [변수] need: 한계 0.1을 얻는 데 필요한 n = d / 0.1² = 100000
need = round(1000 / 0.1 ** 2)                     # ④
# [연결] 100000 → 본문 3절 표의 마지막 행
print(need)
```

**문제**: n = 30일 때 슬라이드 한계 $\sqrt{d/n}$를 d = 2ⁿ과 d = 1000에 대해 구하고, d = 1000에서 한계가 0.1이 되려면 n이 얼마여야 하나?

**주어진 값**:
- $n = 30$ ([학습 데이터](../../00_%EB%94%A5%EB%9F%AC%EB%8B%9D_%EC%9A%A9%EC%96%B4%EC%82%AC%EC%A0%84.md#training-data-test-data-%ED%95%99%EC%8A%B5-%EB%8D%B0%EC%9D%B4%ED%84%B0%EC%99%80-%EC%8B%9C%ED%97%98-%EB%8D%B0%EC%9D%B4%ED%84%B0) 수)
- $d = 2^{30}$, $d = 1000$ (두 경우의 d)
- 목표 한계 $0.1$

**풀이**
1. 식을 그대로 쓴다: 한계 $= \sqrt{d / n}$, 거꾸로 $n = d / \text{한계}^2$
2. $d = 2^{30}$을 대입한다: 한계 $= \sqrt{2^{30} / 30}$
3. (②) 거듭제곱을 푼다 (2를 30번 곱한 값): $2^{30} = 1{,}073{,}741{,}824$ 이므로 한계 $= \sqrt{1{,}073{,}741{,}824 / 30}$
4. 나눗셈을 한다: $1{,}073{,}741{,}824 \div 30 = 35{,}791{,}394.13$ 이므로 한계 $= \sqrt{35{,}791{,}394.13}$
5. 제곱근을 구한다 (계산기): 한계 $= 5982.59$
6. $d = 1000$을 대입한다: 한계 $= \sqrt{1000 / 30}$
7. (③) 나눗셈을 한다: $1000 \div 30 = 33.33$ 이므로 한계 $= \sqrt{33.33}$
8. 제곱근을 구한다 (계산기): 한계 $= 5.7735$
9. (④) 필요한 n의 식에 대입한다: $n = 1000 / 0.1^2$
10. 제곱한다: $0.1^2 = 0.01$ 이므로 $n = 1000 / 0.01$
11. 나눗셈을 한다: $1000 \div 0.01 = 100{,}000$

**답**: d = 2³⁰이면 **5982.59**, d = 1000이면 **5.7735**. d = 1000에서 한계 0.1을 얻으려면 n = **100,000**개가 필요하다. d가 n과 함께 $2^n$으로 커지면 n을 아무리 늘려도 이런 지점이 오지 않는다.

</details>
